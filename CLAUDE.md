## Project

**Price Tracker** — standalone Swedish grocery and pharmacy price tracker, originally extracted from the `ai-agent-platform` monolith at `/home/magnus/dev/ai-agent-platform`. Tracks prices at ICA, Willys, Apotea, Med24, Doz, Kronans Apotek, Apohem, Rusta, Clas Ohlson, and Lyko; exposes its capabilities to the agent platform via an MCP server. Single-**owner**: one admin (Magnus) who may change anything, and read-only access for everyone else the Entra gate authenticates (v0.29.0 — → Auth bullet); one tenant of data either way. Entra ID is enforced at the upstream Traefik + auth-middleware ingress (managed via Dokploy), not inside this app.

**Status (2026-07-28): the extraction is done and this is a live product.** It is deployed in prod. Phase 04.1 — package data moved from `Product` to `ProductStore` — is built, verified, and deployed. Test suite: **648 passing** (that total includes 33 Postgres integration tests; with no DB reachable they skip cleanly and you get `615 passed, 33 skipped`). No local Postgres is needed to run the integration tier — `docker run --rm -e POSTGRES_USER=price_tracker -e POSTGRES_PASSWORD=price_tracker -e POSTGRES_DB=price_tracker -p 55432:5432 postgres:16` plus `TEST_DATABASE_URL` pointed at it runs all of it, and that is how a schema change should be verified before it is tagged.

**Deploy state (2026-07-29): prod runs `v0.32.1`; everything from `v0.33.0` (Swedish förmiddag window) through `v0.37.0` (Lyko) is tagged and built, waiting on ONE deploy bump — which now also applies TWO alembic revisions (`0009_check_attempts`, `0010_seed_lyko`).** Backup export checked against the live instance (on v0.26.0): 15 products / 38 links / 41 history rows, 38 KB, format 1.1. **This line goes stale the moment a tag is cut, so never trust it on its own** — `git tag | tail -1` is the newest tag and `ssh magnus@192.168.10.223 "sudo docker inspect price-tracker --format '{{.Config.Image}}'"` is what prod actually runs. Deploying is a one-line bump of the pinned tag in the home-server repo's `compose/dokploy-apps/price-tracker/docker-compose.yml` — that repo is not this repo, and the release is not live until that bump lands.

**Since 04.1 — what changed, and where the rule now lives.** This is an index, not the documentation: every durable rule sits in **Architecture** or **Gotchas** below, next to the code it governs. Do not grow this list into a changelog — `git log` is the changelog.

- **v0.20–v0.22:** `category` became a fixed ordered enum (→ category bullet); quick-add strips the brand out of the suggested name (→ Quick-add).
- **v0.14–v0.25.0 — anti-WAF:** shared politeness ledger with jitter, honest failure on a bot wall, scheduler auto-pause during adds, per-store circuit breaker (→ rate-limiter, fetcher and scheduler bullets). **ICA sits behind AWS WAF and its HTTP 202 is a JS challenge** — `curl_cffi` shipped in v0.30.0 (→ transport bullet); a headless browser that mints an `aws-waf-token` remains the one un-built lever.
- **v0.28.0 — the breaker became everyone's, and HTTP/2:** the circuit breaker moved out of the scheduler into `infra/store_block.py` and now gates every caller, its cooldown escalates, and the fetcher speaks h2 (→ store-block, fetcher and Willys-API bullets).
- **v0.28.2 — breaker callers agree, and the Willys API speaks Chrome too:** the scheduler now resets breaker strikes on the same "reached the store" predicate as the interactive paths, and the Willys REST call rides the shared fetcher client and raises `StoreBlockedError` on a wall instead of degrading to "product missing" (→ store-block and Willys-API bullets).
- **v0.30.0 — curl_cffi is the fetch transport:** Chrome's TLS and h2 fingerprint, behind an env switch so the benefit can actually be measured rather than assumed (→ transport bullet).
- **v0.30.1 — the XHR repaint stopped wearing navigation headers:** `fetch_json` removes `sec-fetch-user`/`upgrade-insecure-requests` and claims the product page as Referer, and the bot-wall log line names the transport so the A/B is a grep (→ Willys-API and transport bullets).
- **v0.31.0 — Rusta, via a new store-HTML ladder tier:** the extraction ladder gained a page-state tier between store-API and JSON-LD, because Rusta's JSON-LD hides the ordinarie at a rea and the printed jämförpris (→ Rusta bullet + Quick-add).
- **v0.32.0 — Clas Ohlson, second store-HTML extractor:** same JSON-LD blind spot as Rusta, but the riches live in BEM price markup instead of hydration state; the extractor composes the shared JsonLdExtractor and refuses on any disagreement (→ Clas Ohlson bullet).
- **v0.32.1 — the LLM can no longer invent an inverted offer:** an offer is what you PAY, lower than `price_sek` by definition, but a model reading "2 för 130 kr" reported the bundle price as the offer (prod: price 69.46, "offer" 130.00 — and `effective_price = coalesce(offer, price)` re-priced the link to 130 in every ranking). `offer >= price` is now refused wholesale (price + type + details) in BOTH the enrichment merge and `_extract_with_model`.
- **v0.37.0 — Lyko, third store-HTML extractor:** same Avensia Nitro platform as Rusta, but its `comparisonPrices` is a LIST of other prices rather than a jämförpris, and only two of its four types are an ordinarie the store charged (→ Lyko bullet).
- **v0.36.0 — Statistik, a page of cross-product questions:** per-product trend, store comparison on a MATCHED basket, offer quality (how often a campaign is actually cheapest), and coverage counts that link into the product facets — computed by `domain/stats.py`, read-only by construction (→ statistics bullet).
- **v0.35.0 — the tracker records what the stores REFUSE, not just what they say:** a new `check_attempts` row per outgoing check (outcome, ladder tier, duration), because a failed or walled check wrote nothing at all and the only trace was a log buffer that resets on restart (→ check-attempts bullet).
- **v0.34.0 — the portal answers "vad ska jag köpa?" instead of listing everything:** Erbjudanden groups on whether an offer is actually the cheapest way to buy the product and ranks on the kr/unit margin (recency is a column now, not the order); the product row lost three of its five buttons; the product list filters in the browser on four facets (→ portal-UI bullet).
- **v0.33.0 — the förmiddag window became Swedish:** `schedule.py` computes the 06–12 window and the weekday in Europe/Stockholm and converts back to naive UTC, instead of applying the civil rule directly on UTC (which silently meant 08–14 Swedish summer time and judged "måndag" by a clock whose Monday starts 02:00 Swedish) (→ schedule bullet).
- **v0.29.3 — 405 is a wall too:** ICA refuses us with HTTP 405 as well as 202, and the fetcher was reading it as a legitimate page error (→ fetcher bullet).
- **v0.29.2 — a block is the store's state, not the link's:** the link that discovers a wall is deferred by the breaker instead of +24h, and a wall no longer counts as a check (→ scheduler bullet).
- **v0.29.1 — the block cooldown is 5 minutes, not 30:** an ICA wall was measured lifting within 17 minutes for the identical client and IP, so the base was sized for the wrong failure mode (→ store-block and fetcher bullets).
- **v0.29.0 — read-only for everyone else:** the app stopped being single-user; `ALLOWED_ENTRA_EMAIL` became the admin and every other Entra identity became a reader (→ Auth bullet + Gotcha 7).
- **v0.25.1 — Willys quick-add:** the preview gained an API-first tier, because Willys is an SPA whose HTML has no price at all (→ Quick-add).
- **v0.25.2 / v0.25.3 — campaign prices:** the two store families were wrong in opposite directions and now agree (→ campaign-price bullet).
- **v0.26.0 — backup repaired:** the export had rotted into a backup of nothing (→ export/import bullet), and alembic was silencing app logging (→ Gotcha 5).
- **v0.27.1 — the LLM cascade now says which caller ran it.** `extract_price` and `enrich_with_llm` share `_run_llm_cascade`, which logged `"Price extracted with <model>"` for both. So a *successful* JSON-LD check followed by routine enrichment logged `Price extracted via JSON-LD` → `Trying deepseek…` → `Price extracted with deepseek`, which reads exactly like "the structured parse failed and fell back to an LLM". It sent a debugging session after a store block that had not happened. Enrichment now logs `Enrichment answered with <model>`. **Enrichment can never change the price** — `price_sek` is not in `_ENRICHABLE_FIELDS` and only `None` fields are filled — so that sequence is normal and the JSON-LD price stands. **And it can no longer invent an inverted offer (v0.32.1):** an enriched or LLM-extracted `offer_price_sek >= price_sek` is refused together with its type/details, because a model reading a multi-buy ("2 för 130 kr") reports the bundle price as the per-unit offer.
- **v0.27.0 — watches became editable:** `PUT /watches/{id}` had no dialog behind it, and its `if value is not None` guards made every target a one-way door — settable, never removable. The endpoint now keys on `model_fields_set`, so a **sent null clears** while an absent key is still left alone; the dialog sends every field on save. Both targets are exposed, because the scheduler alerts on `target_price_sek` AND `unit_price_target_sek` and showing only one leaves an invisible trigger on a watch restored from a backup.

## Technology Stack

Changing a stack component is a real decision — discuss it first. Everything below is what the code actually uses.

- **Language/runtime:** Python 3.12
- **Web:** FastAPI + uvicorn
- **DB:** PostgreSQL via SQLAlchemy 2.0 (asyncio) + Alembic. **Tests run against real Postgres, not SQLite** — the models use `postgresql.UUID` and `JSONB`, which aiosqlite cannot compile. `tests/conftest.py` drops and recreates a throwaway `price_tracker_test` database; if no DB is reachable, the integration tier skips cleanly. (`aiosqlite` is still declared in `pyproject.toml` but no code imports it — vestigial, safe to remove.)
- **HTTP client:** **curl_cffi** for store fetches (Chrome TLS/JA3 + h2 impersonation; env `FETCHER_TRANSPORT=httpx` flips back), httpx everywhere else (OpenRouter, Resend) and as the fallback — with **HTTP/2 enabled** (`httpx[http2]` → `h2`). See the fetcher and transport bullets: the fingerprint is a bot-detection concern, not a performance choice
- **Email:** Resend HTTP API (`https://api.resend.com/emails`) — same provider as the source platform; no SMTP (D-32)
- **LLM:** OpenRouter direct at `https://openrouter.ai/api/v1` (OpenAI-compatible) — no LiteLLM proxy
- **MCP:** `fastmcp` (mounts on FastAPI)
- **Auth (UI):** IAP header trust — reads `X-Auth-Request-Email` forwarded by the upstream Traefik + auth-middleware ingress (managed via Dokploy); no in-app OIDC client
- **Auth (MCP):** static bearer token (`MCP_BEARER_TOKEN`)
- **Frontend:** server-rendered HTML + vanilla JS + Chart.js (ported from source — no SPA framework)
- **Tests:** pytest, pytest-asyncio
- **Lint/format:** ruff 0.14.4 (config inherited from the source repo). `ruff format` replaces black — do not add black. mypy is **not** carried over yet (the source had it; typing 10,800 ported lines is its own task).
- **CI:** `.github/workflows/ci.yml` — ruff check → ruff format --check → pytest, on every push and PR, against a Postgres 16 service so the integration tests actually run. (`release.yml` only builds the image on a version tag.)
- **Packaging:** poetry
- **Container:** `python:3.12-slim` Docker image; docker-compose with Traefik labels

## Conventions

**The port doctrine is over. Read this before you "restore" anything.**

Phases 1–3 were a byte-equivalent port from the monolith, and the rule then was: don't refactor, don't fix known shortcomings, don't add abstractions — so the result stayed diffable against the source. **That rule expired when the port landed. It no longer governs this repo.**

This is now an ordinary product repo:
- **Refactoring, model changes, and bug fixes are allowed and expected.** Don't ask "does this match the source?" — ask "is this right?"
- **Phase 04.1 was a deliberate, verified, deployed model change** (package data moved to the store link). It is not drift from the port. **Reverting it in the name of "the source repo did it differently" would be a regression** — the source repo is being deleted (Phase 5).

**Language — one track (decided 2026-07-14):**
- **Swedish** for everything a user sees: UI strings, toasts, user-facing `HTTPException(detail=...)`, email, MCP tool output. The page declares `lang="sv"`.
- **English** for everything a developer sees: identifiers, DB columns, JSON keys / wire contracts, logs, docstrings, comments, commit messages, and internal 500-level errors.
- Glossary: produkt · butik · länk · förpackning · mängd · **jfr-pris** (headings; the shelf-label word — value labels stay "kr/st"-style) · bevakning · erbjudande · i lager · Åtgärder.

**Comments:** explain WHY, not WHAT. The non-obvious invariants in `models.py` / `pricing.py` are commented on purpose — don't strip them.

**Data model (6 tables):** `stores`, `products`, `product_stores`, `price_points`, `watches`, `check_attempts` (v0.35.0 — → check-attempts bullet). Tenant-scoped tables carry a `tenant_id` UUID column.

**The 04.1 shape — a product is abstract, a link is concrete:**

- **`package_size` + `package_quantity` live on `ProductStore`** (the link), not on `Product`. `unit` (st/liter/kg) stays on `Product`. The product is the abstract thing you compare; the link is the specific package a specific store sells.
- **`PricePoint.unit_price_sek` is GONE.** kr/unit is **computed on read** from `price / link.package_quantity`, exposed as the hybrid `PricePoint.computed_unit_price_sek` (Python + SQL modes). **The single definition lives in `src/domain/pricing.py`. Do not write a second one anywhere.** Correcting a link's amount retroactively fixes all its history — that's the point.
- **`PricePoint.store_unit_price_sek`** is the store's *printed* comparison price. It is displayed beside the computed value and **never sorted on** — stores print in different units, so sorting on it compares kr/kg against kr/st.
- **`ProductStore.scraped_package_quantity`** is what the page said, kept as *evidence*. Typed input is *intent*. Evidence autofills an empty field and **flags** a conflict; it never overwrites intent.
- **A campaign is ORDINARIE + OFFER, identically in every store (v0.25.2–v0.25.3):** `price_sek` is the ordinarie price, `offer_price_sek` is what you pay now, `offer_type="kampanj"`. Both extractors used to be wrong, in opposite directions. **Willys API:** `priceValue` is ordinarie and `savingsAmount` the per-unit discount, so the offer is `priceValue - savingsAmount` (verified 21.29 − 3.39 = 17.90 = `potentialPromotions[].price`); the old code ADDED the saving, inventing a "regular" price that appears nowhere in the API. **JSON-LD pharmacies:** the struck-through ordinarie hides in the offer's `priceSpecification` — `ListPrice` (Apohem) or `StrikethroughPrice` (Kronans), dict or list, http or https — and counts only when it is **higher** than `offers.price`; the old code kept the current price as `price_sek` and discarded ordinarie, so a pharmacy sale never surfaced in "Erbjudanden". A `UnitPriceSpecification` bearing only the jfr-pris is not an ordinarie. **kr/unit is unaffected by all of this** — it ranks on `effective_price_sek = coalesce(offer, price)`, which is the price paid either way.
- **`ProductStore.store_label` (v0.6.0)** is the link's optional display store name ("ICA Maxi Sandviken") for chains that price per physical butik — two ICA butiker are two links under the ONE chain-level `Store` row (whose slug drives the extractors; never add per-butik Store rows). `domain.models.link_store_name` (label wins, chain name is fallback) is the single display rule; every store-name emission (links, history, deals, emails, MCP) goes through it. Quick-add suggests the label from the URL's `/stores/<id>/` segment (`quickadd.KNOWN_STORE_LABELS`), and for butiker in `quickadd.SIBLING_STORE_GROUPS` it also offers to create the sister-butik links in the same confirm (v0.7.0) — siblings are created optimistically and left for the scheduler (v0.19.0 stopped fetching them inline: sister butiker share ONE `store_id`/host, so an inline check per sibling was the same-host burst that tripped ICA's WAF, and under the block-aware fetcher a rate-limited fetch is indistinguishable from an absent page, so it would wrongly delete valid siblings). Both tables are per-instance operator config since v0.8.0: env `QUICKADD_STORE_LABELS` / `QUICKADD_SIBLING_GROUPS` (JSON), in-repo defaults are Magnus's butiker, malformed JSON warns and falls back — the repo is public/MIT and a second instance sets its own.
- **The check schedule is a STORE property (v0.13.0):** `Store.check_weekdays` (JSONB list, 0=måndag — ICA `[0]`, Willys `[0, 4]`) + `Store.check_frequency_hours` (72 for the pharmacies), both modes morning-aligned (06–12 — **Europe/Stockholm wall-clock since v0.33.0**: the window and the weekday are computed in `STORE_TIMEZONE` and converted back to the app-wide naive-UTC storage convention, because "förmiddag" and "måndag" are Swedish civil concepts; computed directly on UTC they silently meant 08–14 Swedish summer time, drifted an hour at each DST change, and would judge a check at 00:30 Swedish Monday night as Sunday's. **Instants stay naive UTC everywhere — only the civil-rule computation and the UI's `parseUtc` display layer are timezone-aware; never store local time**). A link's own `check_weekdays`/`check_frequency_hours` are NULL in the normal state = inherit; setting either overrides WHOLESALE. Resolution + next-check time live in `domain/schedule.py` — one definition, used by the scheduler and the admin `/frequency` endpoint alike (its private copy was removed; do not reintroduce one). Quick-add and the add-link dialog ask nothing about scheduling; only the link-edit dialog offers the override.
- **`Product.category` is a fixed ordered enum (v0.20.0–v0.21.0):** the 10 grocery-section values and their in-store walk order live in `domain/categories.py` (THE list). `normalize_category()` coerces free text / an old LLM guess to a canonical value or None (keyword map; `"ost"`/`"fil"` ordered last so they don't swallow `"kosttillskott"`/`"filmjölk"`); `category_sort_index()` is the aisle-order sort key (ready for a future shopping-list sort; the product list still sorts by name). The UI `<select>` is server-injected from the list in `render_admin` (no second copy) and `test_static_gates.py` guards the `<!--CATEGORY_OPTIONS-->` placeholder. Server normalises on create/update/import. Free text is gone; "Kött, Chark & Deli" merged the old meat/chark/fish split.
- **The politeness ledger is SHARED and lives in `infra/rate_limiter.py` (v0.14.0):** `StoreRateLimiter` (process-wide singleton via `providers.get_rate_limiter`, injected into the scheduler) is THE per-store request throttle — reserve-a-slot, keyed by store id. The scheduler spaces its background checks 60 s apart (`RATE_LIMIT_DELAY`); the **interactive** fetches (quick-add preview, first check, manual re-check in `admin.py`) now go through the SAME ledger with a short interval and a `max_wait` cap (env `QUICKADD_RATE_LIMIT_DELAY`=5 s, `QUICKADD_MAX_WAIT`=10 s) so they can't burst a store's WAF while never stalling a human on a background reservation. **Both cadences carry jitter on top of the floor (v0.24.0)** — `RATE_LIMIT_JITTER`=30 s background, env `QUICKADD_RATE_LIMIT_JITTER`=3 s interactive — so a store isn't hit on a clockwork beat; jitter only extends the *next* slot, never the current caller's wait (`max_wait` still holds). Before the shared ledger, interactive fetches bypassed all throttling — that is what let quick-add + scheduler checks trip ICA into HTTP 202/403. **Do not reintroduce the scheduler's old private `_last_request_at` dict.**
- **The fetcher fails honestly on a bot wall (v0.14.0; hardened v0.25.0):** `WebFetcher.fetch` never treats a wall as a page (the old `raise_for_status()` let a 202 through as an empty page → "metadata extraction failed" instead of "blocked"). **WAF statuses (HTTP 202/403/405/429) FAIL FAST — no retry — and return `blocked=True`:** ICA's 202 is an AWS WAF JS challenge (`awsWafCookieDomainList`/`gokuProps`, needs a real browser to mint an `aws-waf-token`) that a few-second retry cannot solve and only reinforces the IP flag. Only *transient* failures (5xx, network error, empty body) get the short bounded retry (`_RETRY_DELAYS_SECONDS`); a hard 4xx (404/410) fails fast. **405 is a wall, not a method error (v0.29.3, from prod evidence).** ICA answers 405 to a plain GET while it is walling us: we only ever GET, these are pages a browser opens, and the SAME urls returned 200, 405 AND 202 within one morning (Ketchup priced 06:42 → 405 at 10:01; Tortilla priced 09:42 → 405 at 10:03; Kaviar 405 at 07:56 → 202 at 10:13). The 405s arrive in RUNS starting on the first probe after a cooldown lapses. Classified as a hard 4xx it left `blocked=False`, so the breaker never re-tripped and the scheduler fed ICA at its 60-90 s cadence straight through the wall — and each 405 pushed its link +24h out of the förmiddag window. A genuine 404/410 is still a hard error and must NOT cool the store down. The `blocked` flag propagates `fetcher → perform_price_check` (`PriceCheckOutcome.blocked`) `→` **every caller** — scheduler AND the interactive endpoints — into the shared registry (→ store-block bullet). **The fetcher logs at the point of detection (v0.28.0):** a bot wall, a hard 4xx and a give-up-after-retries each get their own WARNING, because a WAF challenge used to produce *no log line at all* and the first evidence was a caller's generic "fetch failed". Fingerprint: consistent Chrome UA + `sec-ch-ua` + `sec-fetch-*` (bump `chrome_major` when stale) **plus HTTP/2 (v0.28.0, `httpx[http2]` → `h2`)** — a client claiming to be Chrome and then speaking HTTP/1.1 to a CDN contradicts itself at the connection layer, before a header is read; verified h2 negotiates against ica.se, willys.se and apotea.se — and **the negotiated protocol is logged once per host per process (v0.28.3)**, INFO for `HTTP/2` and WARNING for a 1.1 downgrade, so prod logs can prove which protocol each store actually got. None of this beats the JS challenge or the TLS/JA3 layer — `curl_cffi` shipped in v0.30.0 for the TLS/h2 half (→ transport bullet); a headless browser remains the un-built lever for the JS challenge itself. **But measure before building either (2026-07-26).** A probe run against the exact URL that had just been walled, 17 minutes after the 202: **plain httpx with these very headers got the full 510 KB product page**, from the same public IP that had just been refused. And the requests around the block were ~2 minutes apart — *slower* than the scheduler's own cadence. So that challenge was neither rate-driven nor fingerprint-driven; it was **sampled**. `curl_cffi` was installed and tried in the same probe (it also got 200) but proved nothing, because the control had already succeeded. **That probe also produced a wrong claim worth not repeating: its `http_version: 3` was read as HTTP/3. In curl's enum 3 is HTTP/2; HTTP/3 is 30.** curl_cffi buys TLS/JA3, h2 SETTINGS and header order — not a protocol upgrade (`_normalise_http_version` in the fetcher now encodes that, with a test). **It was ported anyway in v0.30.0** — not on the strength of the theory, but because the change is small, reversible and finally MEASURABLE (→ transport bullet). A headless browser that mints an `aws-waf-token` and hands it to the cheap fetcher remains the only lever that addresses the JS challenge itself; curl_cffi cannot solve one.
- **The fetch transport is swappable and instrumented (v0.30.0):** `WebFetcher` builds a **curl_cffi** `AsyncSession` (`impersonate="chrome"`) by default and an httpx client when env **`FETCHER_TRANSPORT=httpx`** says so; `fetcher.transport` records which one got built and every protocol **and bot-wall** log line names it (the wall line since v0.30.1 — counting blocks per transport is the whole measurement, so it must be a plain grep). curl_cffi closes the half of the fingerprint headers cannot reach — the **TLS ClientHello (JA3)** and the **HTTP/2 SETTINGS/priority frames** — because a client sending Chrome's headers over an OpenSSL-default handshake contradicts itself before a byte of HTTP is read. **It does NOT solve the JS challenge** (no JS engine, so no `aws-waf-token` ever), and its benefit against ICA is PROMISING BUT NOT YET PROVEN. First prod datapoint (2026-07-28): the 14 ICA links walled under httpx on Monday morning (405/202 runs) ALL passed under curl_cffi within 24h — same URLs, same IP, same förmiddag window — 15/15 clean fetches and zero `Bot wall` lines. But the 2026-07-26 probe showed ICA's challenge behaving *sampled*, so one clean day is a datapoint, not a verdict: judge on several Monday runs (`docker logs … | grep -c 'Bot wall'` — every wall line names its transport since v0.30.1). The env var stays the rollback: one restart flips to httpx for a control week. Under curl_cffi the UA/`sec-ch-ua` come from the impersonation profile: **never hand-write them on top**, that re-creates the contradiction (`_CHROME_MAJOR` feeds the httpx path only). A missing or broken native lib degrades to httpx with a WARNING rather than leaving the app with no fetcher at all. `curl-cffi` ships prebuilt abi3 wheels, so the image needs no toolchain; **httpx stays regardless** — OpenRouter and Resend use it, and it is the fallback.
- **The scheduler self-defends against store WAFs (v0.23.0 pause, v0.25.0 breaker):** (1) **Auto-pause** — the add flows (`/quick-add/preview`, `/quick-add`, `POST /products/{id}/stores`) call `scheduler.pause_for(...)`, silencing background checks for a window each add pushes forward (env `SCHEDULER_ADD_PAUSE_MINUTES`=60) so a burst of manual adds can't race the scheduler into a store's WAF; `paused_until` shows in `/scheduler/status` and the portal status box (PAUSAD — parse it with `parseUtc`, it's naive UTC). (2) **Per-store circuit breaker** — see the store-block bullet below; the scheduler is now one of its clients, not its owner. **A failed weekday-scheduled check reschedules +24h, but a BLOCKED one does not (v0.29.2):** a wall is the store's state, not the link's failure, so the discovering link is deferred to the breaker's `blocked_until` — the same deferral the skip branch already gave every *other* due link of that store. Before that, whichever link happened to sit first in the ASC due queue took a 24h penalty for being first while its siblings resumed in minutes, and since +24h keeps the *clock time the wall happened at*, a link blocked at 23:16 retried at 23:16 the next night, and the night after — permanently outside the 06–12 window `domain/schedule.py` exists to hold it in. That was the only mechanism moving checks out of that window. **A blocked link also no longer sets `last_checked_at`** (we never saw the page), so "Senast kollad" and the portal's freshness line stop reporting a wall as fresh data; a fetch that *reached* the store and yielded no price still counts, because the store answered.
- **The circuit breaker is SHARED and lives in `infra/store_block.py` (v0.28.0):** `StoreBlockRegistry` (process-wide singleton via `providers.get_block_registry`, injected into the scheduler) is THE record of "this store is walling us right now". It answers *whether* we may talk to a store; the ledger answers *how fast*. **Every outgoing store call consults it and reports back** — the scheduler skips a cooled store's due links without fetching (deferring `next_check_at` past the cooldown), and the interactive endpoints (`/quick-add/preview`, `/check/{id}`) refuse with **HTTP 503 + `Retry-After`** and a Swedish "butiken blockerar oss" message. It was a private dict inside `PriceCheckScheduler` until v0.28.0, which meant only *background* checks stood down: a human seeing "kunde inte hämta sidan" could mash "Kolla nu" straight into an active AWS WAF challenge, which is precisely what keeps an IP flag alive. Conversely a block found interactively now silences the scheduler. **The cooldown escalates** — base × 2ⁿ, env `SCHEDULER_STORE_BLOCK_COOLDOWN_MINUTES`=**5 since v0.29.1** (was 30; name kept for compatibility) capped by `STORE_BLOCK_MAX_COOLDOWN_MINUTES`=240 — and **the first page that loads resets the strike count**: the predicate is "reached the store" (`failure_reason != "fetch_failed"` — a fetch that succeeded but yielded no price still counts as "the store answered"), and since v0.28.2 the scheduler and the interactive paths use that SAME predicate (the scheduler briefly keyed on full success, so a store whose page layout broke kept stale strikes and the next real block escalated from the wrong level). A lapsed cooldown clears but the strike count survives, so the probe after a lapse escalates rather than restarting at base. In-memory/single-process like the add-pause; the scheduler's DB-side `next_check_at` deferral survives a restart anyway. `blocked_stores` is in `/scheduler/status` and the portal status box shows **BLOCKERAD** (outranking PAUSAD).
- **Every outgoing store request goes through the ledger — including the Willys REST API (v0.28.0).** `WillysApiExtractor._fetch_product` fired straight out of `httpx` with no slot and DEBUG-only logging, so a Willys price check made **two** requests to `www.willys.se` (the page fetch in `perform_price_check`, then the API call from the extraction ladder) while spending **one** slot, and a bot wall there was indistinguishable from a missing product. It now reserves a slot keyed `"host:www.willys.se"` (the extractor never sees a store id, and the host is what a WAF rate-limits) and logs 202/403/429 as a bot wall at WARNING. **Since v0.28.2 the API call also rides the SHARED `WebFetcher` client** (`fetch_json` — same Chrome fingerprint, same h2 connection, per-request headers repainted as an XHR) instead of a per-call bare `httpx` client that announced `python-httpx` over HTTP/1.1 to the very host the page fetch had just spoken Chrome-h2 to. **Since v0.30.1 the repaint also REMOVES the navigation-only headers** (`sec-fetch-user`, `upgrade-insecure-requests` — a real Chrome XHR never sends them, but both transports paint them onto every request) **and claims the product page as `Referer`** (`sec-fetch-site: same-origin` with no Referer contradicts itself). Removal is transport-specific and non-obvious: an empty string value does NOT remove a header on either transport — both SEND it empty, echo-verified — so curl_cffi gets `None` (its "disable this header" marker) and httpx gets the header deleted from a built request. **A wall in the API raises `domain.result.StoreBlockedError`** rather than returning None (None means "product missing" and fell through to a pointless LLM run that ended as a strike-RESETTING `no_price`): the parser lets it through the ladder's `except Exception`, `perform_price_check` turns it into a `blocked=True` outcome, and the quick-add preview's API tier trips the breaker + answers 503 instead of firing the page fetch at the same walled host. The only outgoing calls that are deliberately *not* store-gated are OpenRouter (`domain/parser.py`) and Resend (`infra/email.py`) — neither is a tracked store.

- **`uq_product_store(product_id, store_id)` is DROPPED; `store_url` is globally unique** (`uq_product_stores_store_url`). One product can have several links at the same store (different pack sizes). The URL is the link's natural key. **An AST gate in `tests/test_static_gates.py` fails any query in `src/` that resolves a link by the `(product_id, store_id)` pair** — if that test fires, your query is built on the pre-04.1 model, not on a lint nit.

**Export/import is THE backup, and a backup is judged by what it leaves out (v0.26.0):** `GET /export` writes **every product in the tenant**. It used to inner-join *active watches*, so a tracker with products but no watch exported `products: []` under a **200 OK** — 15 prod products became a 205-byte file. A watch is one optional attribute of a product, never the condition for saving it. Format **1.1** carries `store_label` and keys each history row on `store_url` (the link's natural key — product+slug cannot address one of several links at one store, the pre-04.1 shape the AST gate forbids). `POST /import` restores products, links, watches **and price history**, deduped on `(link, checked_at)` so re-importing is idempotent; history used to be exported and then silently dropped. A 1.0 file still imports — its unaddressable history rows are skipped with a warning, never guessed at. The portal's button passes `history_days=0` = ALL history (the 30-day default silently truncated). `tests/test_export_import.py` is a real-Postgres round trip — export, wipe, import, compare — and these endpoints had **no test at all** before it, which is exactly how they rotted.

- **Rusta is read from `window.CURRENT_PAGE`, not from its JSON-LD (v0.31.0):** Rusta (an Avensia Nitro storefront) server-renders both, but the JSON-LD carries only the CURRENT price — at a rea (verified live 2026-07-27: Hängstol Sorrento, current 1899 / original 2999) extracting it would record the campaign price as `price_sek`, the exact ordinarie/offer inversion v0.25.2/v0.25.3 fixed elsewhere. `domain/extractors/rusta.py` parses the CURRENT_PAGE hydration JSON from the already-fetched page: `original` → `price_sek`, `current` → offer when lower, `comparisonPrice`/`comparisonUnit` → the printed jfr-pris (absent from JSON-LD entirely), `stock` → in-stock, and `subTitle` ("50 ml Invisible Black & White") → package evidence via `parse_package_from_name`. The node is verified against the URL's trailing article code (root or `variations[]` — color siblings share one page); a mismatch returns None rather than recording a foreign product at 0.98 confidence. **The extractor lives in THE `_HTML_EXTRACTORS` registry in `domain/parser.py`** (`get_html_extractor` — same sharing contract as `_API_EXTRACTORS`, used by the price ladder AND quick-add preview): a store-HTML extractor parses the page the pipeline already fetched, makes no HTTP calls of its own, needs no ledger slot and can never raise `StoreBlockedError`. Ladder order is store-API → **store-HTML** → JSON-LD → LLM; every Rusta parse failure degrades to JSON-LD (right price outside campaigns), never to a failed check. Rusta runs in interval mode (72h default, no offer weekday) and its sale prices surface only via this tier — treat "Rusta rea not flagged" as "CURRENT_PAGE changed shape", and check the `Page-state extractor` WARNING in the logs.

- **Clas Ohlson is JSON-LD *plus* its BEM price markup (v0.32.0):** same blind spot as Rusta — the JSON-LD carries only the current price (verified live 2026-07-27: Braun 44-6051, JSON-LD 499 while the page shows ordinarie 999,00) and no jämförpris — but hybris renders JSP markup, not hydration state, so `domain/extractors/clasohlson.py` reads the stable BEM price section instead: `product__old-price`/`product__discount-price` at a rea, `product__comparison-price` ("(1,91/st)") otherwise, anchored on the SKU token in the container class (`product__normal-price 446051000` — the URL's `/p/` digits must prefix it, which is what keeps carousel price blocks out). It **COMPOSES the shared `JsonLdExtractor`** for identity/availability/price rather than re-parsing, and self-checks: markup price ≠ JSON-LD price → WARNING + None, and a markup that adds nothing (no rea, no jfr-pris) → None — plain JSON-LD answers both. NBSP thousands separators ("1 290,00") and `&nbsp;` entities are handled. `extract_metadata_from_html` is deliberately None: Clas Ohlson's JSON-LD names carry the package text ("…, 94-pack"), so quick-add's JSON-LD tier already previews everything.

- **Lyko is read from `window.CURRENT_PAGE`, and its `comparisonPrices` is NOT a jämförpris (v0.37.0):** Lyko runs the same Avensia Nitro platform as Rusta and has the same JSON-LD blind spot (verified live 2026-07-29: N.C.P. Hand Wash 201 publishes `"price": "58"` while selling at 80 % off an ordinarie of 290), so `domain/extractors/lyko.py` reads the hydration state. **But the field that carries kr/liter on Rusta carries something else entirely here**, and a copy-paste would invent campaigns: Lyko's `comparisonPrices` is a LIST of prices to compare against, each with a `type`, and only `ordinary` ("Tid. pris") and `withoutCampaign` ("Utan kampanj") are an ordinarie the store itself charged. **`recommended` ("Rek. pris" — the manufacturer's RRP) and `packageContentSum` ("Utan paketpris" — a gift set's parts bought separately) are excluded on evidence:** across 24 products on one live listing, the first two appeared if and only if Lyko rendered the product as discounted (`useDiscountStyling`/`discountPercent` set) while every `recommended`/`packageContentSum` sat on an undiscounted product — treating an RRP as ordinarie would mark those permanently on sale and fill Erbjudanden with deals that are not deals. When several types qualify the LOWEST wins (a smaller claimed saving is the safer error; the ranking runs on what you pay either way), and an ordinarie at or below the current price is refused outright — the v0.32.1 invariant. **Lyko prints no jämförpris anywhere** (`unitPrice` null on all 24, no "Jämförpris" text on the site), so `store_unit_price_sek` stays None and the computed kr/unit is the only comparison figure — which is why the structured `size`/`unit` ("500 ml" as 500.0 + "ml") matter: package evidence with no title regex, and **deliberately no title fallback**, because a gift set named "Hand Soap A 300 ml & Hand Soap B 300 ml" carries `size: null` and parsing it would read 300 ml for 600 ml of product. **Identity is the URL's LAST path segment against the state's `canonicalUrl`**, not a trailing article code (a Lyko URL is a pure slug) and not the whole path — the same product answers on both a brand path and a category path with `canonicalUrl` pointing at the former, so comparing paths would refuse a page that is fine. A slug matching only a sibling in `variants` is refused: size variants have their own price. **`variantStoreAvailabilityStatus` must never decide stock** — it read "outOfStockInAllStores" on a product in stock and on sale online, because it describes the physical shops; `in_stock` comes from the schema.org availability in the state's own `linkingData`, falling back to `onlineStatus.interactionType`.

**Statistik answers cross-product questions, and `domain/stats.py` is THE definition (v0.36.0).** The page is the bigger sibling of the per-product history modal: what moved, where to shop, what a campaign is worth, and what is blocking a comparison. Four rules make its numbers true, and each of them fails SILENTLY and plausibly if broken:

- **kr/unit is never summed or averaged across products** — milk's kr/l plus cheese's kr/kg is nonsense, the same invariant that keeps `store_unit_price_sek` unsortable. Everything cross-product is a PERCENTAGE against that product's own baseline. That is also why v1 has **no basket index**: an index needs chain-linking to survive a product being added (it is added weekly here), and the per-product table answers the same question without the machinery. Weights ("how much do I buy per month") stay unbuilt and optional — an unweighted view needs no input at all.
- **Store comparison uses a MATCHED basket** — only products at least two stores carry. Over full assortments the number compares what each store happens to SELL, not what it charges. A store with several links for one product competes with its own cheapest pack.
- **Carry forward, never interpolate.** A link checked last Monday holds Monday's price all week — that is what the shelf says. A price observed BEFORE the window is the baseline the period opens at, so narrowing the period cannot empty the table.
- **Absence is not zero.** A product observed once has `change_pct = None` and renders as an em dash: "0,0 %" would be a confident claim about a period we did not watch. Every panel prints what it was computed from, which is why the page needs no "come back in six weeks" gate — it matures on its own.

**The statistics page has no write path, and that is a rule, not an omission (decided 2026-07-28).** Not an auto-tuner, not an "apply this schedule" button. Raising check frequency where prices move most means fetching hardest exactly where the WAF lives, and a wall records no price point — so the product that changes most often would come to look like it had stopped. The loop would eat the measurement it is built on. Weekday and volatility patterns are shown as observations; any schedule change is made by hand in the link dialog. The coverage counts link INTO the Produkter facets rather than repeating the lists there.

**`check_attempts` is what the stores REFUSED to say (v0.35.0).** `price_points` only ever recorded SUCCESS: a failed check writes nothing, and since v0.29.2 a blocked one does not even touch `last_checked_at` (a wall is not an observation). So "how often does ICA actually answer us" was unanswerable from stored data — the only trace was a WARNING in the in-memory ring buffer, which resets on restart. It shipped **before** the statistics page it exists to feed, because a page can be built whenever and history cannot be backfilled.

- **One row per CHECK, not per HTTP request** (a Willys check makes two requests; what is measured is "did we get a price"), and **a skip is not an attempt** — when the breaker is open the scheduler defers a store's due links without fetching, and a row per deferral would measure the schedule instead of the stores.
- **`CheckAttemptLog` writes in its OWN transaction** (`infra/check_log.py`), and that is the design, not a detail: the interactive endpoints raise their HTTPException on a failed or blocked check *before* they commit, so a row added to the request's session is rolled back — losing precisely the attempts worth having. It also **never raises**: telemetry that can kill a price check trades the data for the thing the data is about.
- **The write lives inside `perform_price_check`**, wrapping the flow so every exit — ok / no_price / fetch_failed / blocked, plus an escaped exception as `error` — is recorded from one place. `attempt_log` defaults to None (recording OFF) because several hundred tests drive the flow with mock sessions, so the default cannot be the enforcement: **an AST gate in `test_static_gates.py` fails the build if any `perform_price_check(...)` call in `src/` omits `attempt_log=`.** The quick-add PREVIEW is the one caller that never reaches the flow (it fetches before a link exists), so it records via `_record_store_outcome(..., log_attempt=True)` — `product_store_id` is nullable for exactly that, and `ON DELETE SET NULL` so removing a link cannot fail on an audit row.
- **`domain.result.extraction_source()` is THE reader of `raw_response["source"]`** — the same `isinstance(raw, dict)` dance had been written three times over a loose JSONB dict where a typo returns None and reads as "the LLM answered". It returns the tier verbatim (`willys_api` / `rusta_page` / `clasohlson_page` / `jsonld` / `llm:<model>` / `unknown`), because *which model* answered is what makes cascade spend readable. The LLM path now stamps itself (it was identifiable only by elimination), and the scheduler gained a `checks_page_state` counter: Rusta and Clas Ohlson checks used to fall through to the else and inflate `checks_llm`, the one number anyone reads to judge what the cascade costs, while those tiers call no model at all.
- **Statistics must NEVER feed back into fetch cadence** (decided with Magnus, 2026-07-28). Not automatically, and not via an "apply" button. Raising frequency where prices move most means fetching hardest exactly where the WAF lives, and a wall records no price point — so the product that changes price most often would come to look like it had stopped changing. The loop would eat the measurement it is built on. The planned statistics page is therefore READ-ONLY by construction: no write endpoints at all, weekday patterns shown as observations, and any schedule change made by hand in the link dialog.

**The portal ranks and filters CLIENT-side, and the endpoints keep their contracts (v0.34.0).** Three UI decisions that are easy to undo by accident:

- **Erbjudanden is grouped by whether the offer is actually the cheapest way to buy the product, not by when we checked.** `classifyDeal` splits every deal three ways from numbers `/deals` already returns: **BEST** (`unit_price_sek <= best_alt_unit_price_sek`), **WORSE**, and **UNKNOWN** (either is null — no amount on the link, or the product has no other link). BEST + UNKNOWN render under "Värt att köpa" ranked by the **kr/unit margin over the next-best link**; WORSE goes in a collapsed `<details>`, least-bad first. The discount % is the STORE's framing and ranks nothing — 30 % off a bad price is still a bad price, and ordering on `checked_at` put exactly those rows on top. UNKNOWN rides with the buyable ones deliberately: it is not *known* to be bad. The "Köpvärda erbjudanden" stat counts BEST only (tooltip carries the full breakdown). **`GET /deals` still orders by recency and still returns every offer** — the ranking is a view, and `find_deals`/MCP consumers were not touched.
- **The product ROW is the Länkar button, and each removed action went where its context already lives.** Five buttons per row (Länkar / Länka / Historik / Redigera / Ta bort) meant 75 controls on a 15-product screen, two of which differed by one letter while doing different things. Now: the row opens the links panel, which is what the table leads into — **the visible affordance is the product NAME, a real `<button>`** (focusable, Enter works), with the rest of the row as a quiet convenience target; **the Åtgärder cell is excluded from that target** (`td.row-actions`), because empty space beside two buttons that silently opens a panel is an invisible third button, reported as a graphical bug within a day of shipping v0.34.0. **Länka butik lives IN that panel** (the dialog stacks above it via `#modal-link-store { z-index: 210 }` and refreshes it on save); **Ta bort lives in the edit dialog** beside the fields it destroys, and its confirm names the product and counts the links + history going with it. The card header keeps ONE primary button (Snabbtillägg, the 95 % path); Ny produkt / Exportera / Importera sit in a `<details class="menu">` overflow. **The links panel follows the same shape (v0.34.2):** its row keeps Redigera + Kontrollera nu, and deleting a link lives in the "Redigera länk" dialog as **Ta bort länk** — "Avlänka" was jargon rather than Swedish, and a third button on every link row for something done twice a year. Its confirm names the butik and the package, because "butikslänken" is ambiguous with three of them on screen. **Do not put such a menu inside the products table:** `#products-table-container` is an `overflow-x: auto` box, which computes `overflow-y` to `auto` and clips the last row's dropdown.
- **The product list filters in the browser; `allProducts` is ALWAYS the full list.** `loadProducts` fetches `/products` unfiltered and `renderProducts` filters between the array and the DOM. Before, the search round-tripped per keystroke *and assigned the result to `allProducts`*, so the global list silently meant "whatever the table is filtered to" — which is what the watch dialog's product `<select>` reads. Facets (kategori, butik, status = har erbjudande / saknar mängd / saknar pris) build their `<option>`s **from the data**, so a filter can never be offered that returns nothing. "Sortera: butiksordning" uses `domain/categories.py`'s walk order, read back off the server-injected `#edit-product-category` options — **a view of THE list, never a second copy** (uncategorised sorts last). State lives in `sessionStorage`, **not in the hash**: `currentPage()` parses the whole fragment as a page name. `/products?search=` stays for the REST API and MCP. The wiring binds by element id at top level, so a renamed control throws mid-load and leaves the whole page inert — `test_static_gates.py` gates those ids against the markup.

**MCP surface:** `check_price`, `find_deals`, `compare_stores`, `list_products` — see EXTRACTION.md §5.

**Quick-add (v0.5.0):** `POST /quick-add/preview` + `POST /quick-add` create a product AND its store link from one pasted URL (store matched by hostname, package parsed from the title). **The preview's identity ladder mirrors the price-check ladder: store API → store page-state → JSON-LD → LLM (v0.25.1; page-state tier v0.31.0).** For a store with a structured API — `domain.parser.get_api_extractor`, currently only Willys — it reads identity + package straight off the REST API (`WillysApiExtractor.extract_metadata`) and never fetches the page. That tier exists because **Willys is a client-rendered SPA: its product HTML carries no JSON-LD and no price**, so the HTML→LLM ladder saw an empty shell and returned a blank form. A store in `get_html_extractor` (Rusta and Lyko; Clas Ohlson is registered there but returns None for metadata) gets its identity from the fetched page's hydration state instead (`extract_metadata_from_html`) — Rusta's JSON-LD names are bare ("Deo roll-on Nivea") while CURRENT_PAGE's `subTitle` carries the package text the preview form wants prefilled, and Lyko's `entryName` is already the abstract good with brand AND size stripped ("Hand Wash Refill Milk & Honey" out of "Palmolive Hand Wash Refill Milk & Honey 500 ml") with `size`/`unit` giving the package as numbers. The suggested name is the abstract good — `strip_brand_from_name` drops a leading/trailing brand the source folded in (v0.22.0), so it doesn't double-print beside the brand column. Preview-then-confirm on purpose — the confirm step is where "ny produkt" vs "ny länk på befintlig produkt" gets decided, which keeps quick-add from rebuilding the pre-04.1 one-product-per-pack-size shape. Decision logic is pure functions in `domain/quickadd.py`; full design in `docs/quick-add.md`.

**Auth:** The portal + API are served at the app root (`price.<domain>/`); the `/admin` prefix was dropped (old `/admin` URLs 308-redirect to `/`) — D-28. The UI trusts the `X-Auth-Request-Email` header forwarded by the upstream ingress and validates it against `ALLOWED_ENTRA_EMAIL` (which must match the Entra **UPN**, not necessarily the gmail address).

**Two roles since v0.29.0 — admin writes, everyone else reads.** `ALLOWED_ENTRA_EMAIL` is now the **admin**, not the only allowed user: anyone the upstream Entra gate authenticates is a **reader**. THE gate is `auth.require_admin_for_writes`, mounted **once** as the `APIRouter(dependencies=[...])` in `admin.py` — it authenticates every caller and refuses any method outside `SAFE_METHODS` (`GET`/`HEAD`/`OPTIONS`) from a non-admin. **Deny-by-default and keyed on the HTTP method, not on a per-route marker**, because a decorator you have to remember on 14 write endpoints is a hole waiting for the 15th; `test_static_gates.py` (AUTHZ-01/02) fails the build if the dependency is dropped or a route is registered off a second router. Every read is a GET here, so no exception list exists — and that is by decision: `/export` (a full DB dump) and `/logs` are readable by every reader. `get_principal` is the ONE identity point (`require_auth` resolves through it); a test that overrides only `require_auth` leaves the write gate live and 403s every POST. The UI mirrors the role rather than defining it: `render_admin` stamps `<body class="role-admin|role-reader">`, CSS hides `.admin-only`, and the JS builds row actions off `IS_ADMIN` — the server is still the gate, this only stops offering buttons that can only fail. Before the split, a household member who logged in correctly got a **403 from this app**, which the ingress then dressed as a white page reading "Found" (→ Gotcha 7). Entra ID enforcement itself is **live in production since 2026-07-09**: oauth2-proxy v7.15.2 + Traefik `forwardAuth` (`entra-auth@file`), email claim = `preferred_username`/UPN, managed in the home-server repo — not in this app. The MCP server is served at `price.<domain>/mcp/` (no `mcp.` subdomain — a path-scoped, un-gated Traefik router with explicit priority bypasses the Entra gate for `/mcp` only) and is protected by its own static bearer token; without `MCP_BEARER_TOKEN` the endpoint fails closed (503). See EXTRACTION.md §6 for background, though its original in-app-OIDC description was superseded by this IAP header-trust model, and D-18's `mcp.<domain>` subdomain plan was superseded by the `/mcp` path (D-29 in .planning/STATE.md).

## Releasing — shipping is part of the task, not a separate errand

**A fix that is not released is not delivered.** Prod runs a *pinned image tag*, so work that only reaches `main` changes nothing for the person using the app. Unreleased commits used to pile up for days (12 of them by v0.3.2 — a whole ruff/CI rebuild plus the price-history fix, all sitting on `main` doing nothing).

**Standing rule: when a change is user-visible or fixes a real problem, cut a release as the last step of the task — without being asked.** Do it in the same session as the fix.

Release = push a `v*` tag. That is the only trigger; `.github/workflows/release.yml` then builds and pushes `ghcr.io/magter/price-tracker:vX.Y.Z` (+ `:sha-<commit>`) for amd64. Nothing else in this repo deploys anything.

```bash
# 1. main is green and pushed. Never tag a dirty tree or an un-pushed commit —
#    the tag would point at something no one else can fetch.
poetry run ruff check src tests && poetry run ruff format --check src tests && poetry run pytest -q
git push origin main

# 2. The version in pyproject.toml IS the tag. Bump it, commit it, then tag that commit —
#    a tag whose code says a different version is a lie you will read back later.
#    (It said 0.1.0 while prod ran v0.3.2. Don't let that happen again.)
git tag vX.Y.Z && git push origin vX.Y.Z

# 3. Watch the build. A tag that fails to build is not a release.
gh run watch "$(gh run list --workflow=release.yml --limit=1 --json databaseId -q '.[0].databaseId')"
```

**Version choice** (single-user app, so this is deliberately simple):
- **patch** (`v0.3.2` → `v0.3.3`) — a bug fix, a corrected display, an internal cleanup.
- **minor** (`v0.3.x` → `v0.4.0`) — a new capability, a schema change, or anything that alters how the app is operated or deployed.
- A schema change means **a new alembic revision** (additive, on top of the chain — see Gotcha 3 for why a shipped revision is never rewritten in place). The deploy applies it via `alembic upgrade head`; verify with `alembic check`, not `alembic current`.

**Then tell Magnus the tag is built and needs the deploy bump.** Deploying is a one-line change to the pinned tag in the home-server repo's `compose/dokploy-apps/price-tracker/docker-compose.yml` (GitOps split: this repo builds, the platform repo is the deployment truth). **That repo is not this repo — do not edit it from here**, and the release is not live until that bump lands.

Docs-only, planning-only, or test-only commits do **not** earn a tag; they ride along with the next real one.

## Gotchas

Traps that already cost time. Each one **passes silently** — that's why they're here.

1. **`ruff` exists — and `B008`/`S101` are ignored on purpose.** ruff 0.14.4 is a declared dev-dependency, with the config inherited from the source repo (`ai-agent-platform/services/agent`); Phase 1 rewrote `pyproject.toml` from scratch and dropped it, which is why the planning docs kept assuming a ruff that wasn't there. Run `poetry run ruff check src tests` and `poetry run ruff format src tests` (`ruff format` is black-compatible and **replaces** black — do not add black). **Never "fix" `B008`:** it is FastAPI's `Depends()`-in-default-argument pattern, and hoisting the call out of the default argument breaks dependency injection — and with it the auth guard. `S101` is ignored because `assert` is how tests assert. **The test suite is the truth, not the linter:** if an auto-fix turns a test red, the fix was wrong — revert it (`UP017` and `UP032` rewrite real logic, not just style).

2. **`src/api/templates/admin.html` has no `<script>` tag.** It is three fragments split on `<!-- SECTION_SEPARATOR -->` and reassembled in `admin.py` at request time (`admin.py` ~L1877). A gate that extracts the `<script>` body gets **zero bytes**, and `node --check` on empty input **exits 0** — so it passes no matter what you wrote. The working incantation:
   ```bash
   awk '/SECTION_SEPARATOR/{n++;next} n==2' src/api/templates/admin.html > /tmp/admin.js \
     && test -s /tmp/admin.js && node --check /tmp/admin.js
   ```
   Keep the `test -s` guard. And remember: **"the file parses" is not "the page renders."** Verify rendering separately.

3. **Alembic: `0001_initial.py` was rewritten in place** during Phase 04.1. Alembic does not checksum migration bodies, so a database stamped `0001_initial` from BEFORE that rewrite compares equal to head, runs **nothing**, and exits **0** — the app then boots quietly against the **old** schema. **`alembic current` will not reveal this** — it prints the same revision either way. **Only `alembic check` does.** That trap was resolved by the 04.1 volume drop (`README.md` § "Schema reset (Phase 04.1)"). **Since v0.6.0 the chain is normal again:** `0002_store_label` is a real additive revision on top of `0001_initial`, and schema changes from here on are ordinary new revisions applied by `alembic upgrade head` — never rewrite a shipped revision in place again.

4. **TECH DEBT — there are two `get_price_history`.** `src/domain/service.py` has the rich, per-link one, and **only MCP calls it**. `src/api/admin.py` runs its **own duplicate query** for `GET /products/{id}/prices`, and **that** is the one the frontend hits. They have already drifted apart — it was the root cause of the price-history bug (package data never crossed the wire). If you touch price history via the API, you are editing `admin.py`, not `service.py`. Consider collapsing them.

5. **A handler on the app loggers is what silences `docker logs` — `logbuffer.install()` must keep calling `ensure_console_logging()` first (v0.28.1).** Nothing configures the ROOT logger (uvicorn only configures its own `uvicorn*` loggers), so root has no handlers and Python falls back to `logging.lastResort`, which prints WARNING+ to stderr. But `Logger.callHandlers` uses `lastResort` **only when it finds zero handlers anywhere up the chain** — so the instant v0.18.0's ring buffer attached to `domain`/`infra`/`api`, a handler WAS found, the fallback was skipped, and every app record terminated in memory. **Nothing raised and the portal's Loggar page kept working**, which is exactly why it went unnoticed: seven days of prod logs contained no app line at all, only uvicorn access logs. `alembic current`-style checks won't show it either — the only test is to look for a non-uvicorn line in `docker logs`. Note the ordering trap: adding a handler to any app logger *before* root has one re-creates this. Covered by `TestConsoleLoggingSurvivesTheRingBuffer` in `tests/test_logbuffer.py`.

6. **`alembic/env.py` must keep `disable_existing_loggers=False`.** `fileConfig()` defaults that flag to **True**, which sets `disabled = True` on every logger that already exists — including the app's own `domain`/`infra`/`api`. Nothing raises: the loggers simply stop emitting, so app logs and the portal's Loggar buffer go quiet. Invisible when alembic owns the process (the deploy runs it standalone), fatal in any process that ran the app first. It surfaced as two `test_logbuffer` failures the moment a DB-backed test file happened to sort before it — and the tests passed in isolation, which is what makes it a gotcha rather than a bug report.

7. **The ingress replaces the BODY of every 401–403 this app returns, and a 403 keeps its status.** The `entra-auth-errors` Traefik middleware (home-server, `bootstrap-dokploy.sh`) catches `401-403` from the *whole chain* — the forwardAuth's own 401 **and** any 403 the app itself produced — and serves the body of `oauth2-proxy`'s `/oauth2/sign_in?rd=…` instead. Its `statusRewrites` maps **only 401→302**, so a 403 comes back as **403 with a redirect's body**: `<a href="…">Found</a>.` The browser does not follow a 403, so it renders a white page with the word **"Found"** on it — which is what a non-admin user saw before v0.29.0, and reads like a broken app rather than "access denied". Consequences that outlive that fix: **never put user-facing meaning in a 403 detail** — a JSON API 403 reaches the frontend as that HTML, which is why `apiPost/apiPut/apiDelete` in `admin.html` substitute their own Swedish message on 403 instead of echoing the response body. Narrowing the middleware to 401 only would fix it at the source, but that is the **home-server** repo, not this one.

8. **An endpoint with no test rots silently.** `/export` + `/import` had **zero** tests and drifted until the export backed up nothing while still returning 200 OK. Both are now covered by a real-Postgres round trip (`tests/test_export_import.py`). Before trusting any endpoint that no test names, check what it actually returns against real data — a green suite says nothing about code it never calls.
